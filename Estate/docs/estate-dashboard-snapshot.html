mc-colitis-predictor prototype

Architecture: SyntheticMCDataset (procedural 256x256 image generator, ImageDataset ABC interface for zero-code-change real-dataset swap-in) -> feature_extraction.py (23 radiomics features: color/HSV, Sobel edge orientation, DoG band-pass texture, FFT-based blur/sharpness, discontinuity/tear detection) -> model.py (GradientBoostingClassifier + Platt-scaling calibration via CalibratedClassifierCV). Independently re-verified by the parent session rather than trusting the subagent's self-report (which had only run a lighter quick_test.py, not the full suite) -- this caught 3 real defects the agent missed: (1) a pure-Python per-pixel nested-loop box blur in _add_edema made every get_image() call take seconds with no caching, causing tests.py to still be running after 16+ CPU-minutes (same O(H*W)-per-pass-with-huge-constant class of bug as the earlier EUS Math Models segmentation fix) -- fixed by vectorizing via scipy.ndimage.uniform_filter; (2) the vascular_regularity synthetic-parameter's generator rendering was backwards (the 'high regularity' case used a hard binary threshold that produced MORE chaotic edges than the smooth 'low regularity' case), and the raw whole-image edge/Laplacian features for vascular_regularity and granularity were swamped by unrelated noise layers -- fixed by injecting genuine coordinate-warp disorganization scaled to (1-regularity) in the generator, and by switching both features to difference-of-Gaussians band-pass filtering tuned to each layer's actual injected spatial frequency; (3) the model overfit badly on tiny synthetic splits (train AUC 1.0) -- reduced GBM capacity (min_samples_leaf, shallower trees) and, once fixed, found the test's own overfitting assertion was checking an absolute train-AUC ceiling rather than the train/test gap, which flagged a genuinely well-generalizing model (train and test AUC both ~0.97) as a false failure; corrected the assertion to check the gap.
